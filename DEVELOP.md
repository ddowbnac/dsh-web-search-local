# Development

The harness runs on Node.js, so the local engine has two backends and picks one at runtime with a guarded dynamic import. Both are fully local and expose the same thing: same `WebSearchResult` shape, `file://` sources, BM25-style ranking, snippets, and an informed empty on a 0-document corpus. On Node the FTS5 module is never imported, so there is no `bun:sqlite` link error. The web backends use only the global `fetch` (Node >= 18 or Bun) and `node:` builtins, so they run on either.

| Runtime | Backend | Index file | Notes |
|---|---|---|---|
| Node.js (default) | Pure-JS inverted index, hand-rolled BM25 | `index.fallback.json` | Zero dependencies. Node 18+ and Bun. |
| Bun | `bun:sqlite` FTS5 (guarded import, only when the `Bun` global exists) | `index.db` (WAL) | Native `bm25()` + `snippet()`. |

## Build and test

```
bun run build           # bun build src/index.ts --target node --format esm --outdir lib + strip of bundle comments
bun test                # 157 tests (metasearch core + per-upstream parsers + provider, local engine/drivers, plugin shape, client bundle)
bunx tsc --noEmit       # strict typecheck (the sources are type-clean; CI enforces this)
node scripts/smoke.mjs  # offline functional smoke test of the built bundle (also: bun scripts/smoke.mjs)
```

### How it works

- Web provider (`src/web/`):
  - `metasearch/orchestrator.ts`: the fan-out. SearXNG's per-upstream threads become a `Promise.allSettled` of self-catching tasks with composable AbortSignals (caller signal + global deadline + per-upstream timeout), partial-failure diagnostics, and `MetasearchError` when all non-optional upstreams fail.
  - `metasearch/types.ts`: the `SearchEngine` contract, `EngineDiagnostic`, `MetasearchError`, and `EngineError` (typed soft-failures).
  - `metasearch/merge.ts`: pure merge/dedup/score/interleave, a port of `merge_two_main_results` + `calculate_score` + the round-robin balancer. No I/O, unit-tested.
  - `metasearch/url.ts`: URL normalization + dedup identity (port of `MainResult.__hash__`). Divergences: host lowercased, trailing slash stripped, tracking params and param order canonicalized, fragment excluded.
  - `metasearch/http.ts`: shared upstream fetch: Chrome User-Agent, typed HTTP/network/oversize failures, 1.5 MB per-response body budget.
  - `metasearch/engines/duckduckgo.ts`: adapter around the existing keyless scraper. A challenge page is a typed `challenge` failure, not "zero results".
  - `metasearch/engines/bing.ts`: keyless HTML scraper ported from `searx/engines/bing.py` (`b_results`/`b_algo` rows, `b_caption` snippets, `/ck/a?u=a1<base64url>` click-redirect decode).
  - `metasearch/engines/wikipedia.ts`: MediaWiki action API (`list=search`, namespace 0). Strips `searchmatch` markup and converts the API `timestamp` to `publishedAt`.
  - `metasearch/engines/index.ts`: the default upstream set: `[duckduckgo, bing (optional), wikipedia (optional)]`.
  - `duckduckgo.ts`: the keyless HTML scraper, pure unit-tested parser (`result__a` title anchors + `result__snippet` paired by resolved URL), `uddg` redirect decoding, entity decoding, snippet clipping, and ad-row filtering. Also the DuckDuckGo upstream of the metasearch.
  - `provider.ts`: the `web` provider: engine selection, the 20 s budget composed with the caller's signal, informed-empty content on zero hits, mapping to `WEB_ABORTED` / `WEB_PROVIDER_ERROR`, and `lastReport()` (exposed on the seam as `__wslMetasearch`).
- Local corpus engine (`src/engine/`): walks the configured `corpusDirs` (async, bounded worker pool, symlink-safe, per-file skip on error, hard `maxFilesPerBuild` cap of 20,000), extracts text per extension, and stores it in a single on-disk index (FTS5 on Bun, JSON BM25 on Node, incremental via `manifest.json`).
- Providers (`src/provider.ts`, `src/fetch-provider.ts`): the `local` search provider returns `file://` sources (informed empty on a 0-document corpus). The `local` fetch provider reads `file://` from disk and wraps `http(s)://` retrieval.
- Pre-warm + concurrency: the index builds in the background at plugin mount. All index mutation is serialized behind one async mutex, and a re-scan interval avoids re-walking the corpus on every search.
- Settings + UI: the `web-search-local` section registers through `installSection` (persisted to `$DSH_HOME/settings.yaml`, hot-reloaded) plus an optional browser card under Settings -> Plugins (the card consumes the `useLocalSearchCard` selector hook and the `save`/`discard`/`edit`/`resetField` actions injected by the slot renderer). It edits engine, corpus dirs, max results, snippet length, index dir, and auto-reindex, with the same rules as the stock cards: staged edits, per-field "Overridden" badges, reset-to-default, and a save that writes only on confirm.

### Built-in metasearch

`auto` and `searxng` run a simplified port of SearXNG inside the plugin process (TypeScript, `src/web/metasearch/`). The only requirement is outbound HTTPS `fetch`. No Python, no venv, no port, no API key.

- Fan-out: each query runs all three upstreams in parallel (DuckDuckGo first, by registration order). Each upstream is an adapter `{ id, displayName, timeoutMs, weight, search() }` with a pure parser and typed soft-failures (`EngineError`: `http`, `network`, `parse`, `challenge`).
- Budgets: 10 s per upstream inside a 20 s per-search budget. Everything composes with the caller's `AbortSignal`. A slow or hung upstream is dropped and the rest answer within the budget.
- Merge and rank: the dedup identity comes from URL normalization (port of `MainResult.__hash__`, the divergences are listed below). Duplicates merge: the longest title and snippet win, an `https://` URL is preferred, and the rank maps are unioned. The score sums the upstream weight by position (port of `calculate_score`), and the final order uses the historical round-robin balancer: one slot per upstream per rank tier, score-descending within a tier, capped at `maxResults` with snippets clipped to `snippetLength`.
- Upstream set: DuckDuckGo is the only non-optional upstream. Bing and Wikipedia register as `optional`, so a failure cannot kill the search.
- Failures: if every non-optional upstream fails (network error, HTTP >= 400, parse, or challenge), the search throws `WEB_PROVIDER_ERROR` with per-upstream detail. "No results" and "everything is broken" must not look alike to the caller. On partial failure it returns the merged results of the healthy upstreams and exposes per-upstream health on `__wslMetasearch` (`ok`/`failed`/`skipped`, hit count, duration, error text).
- Informed empty: zero hits from healthy upstreams return an empty result that names which upstreams answered and which failed.
- Sandbox: the web path spawns nothing, binds no port, and writes no files. It only needs outbound HTTPS, so it works inside DSH agent sandboxes that forbid children and fixed ports.
- Dates: Wikipedia hits carry `publishedAt` (the API `timestamp`). DuckDuckGo and Bing expose no reliable date.
